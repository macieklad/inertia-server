When building applications using Inertia, each page in your application typically has its own controller / route and a corresponding JavaScript component.
This allows you to retrieve just the data necessary for that page - no API required. With `inertia-server`, working with pages is based on page definitions created by `definePage`.

```ts
const { definePage } = createInertia(...);
```

## Creating page definitions

Page definitions are data-first. Start with the full data shape your page expects, then add modifiers only for props that need special Inertia behavior.

```ts ~/server/inertia.ts
import {
  createInertia,
  deferred,
  deepMerged,
  merged,
  type ModifierTree,
  type PageProps,
} from 'inertia-server';

type HomePageData = {
  title: string;
  description: string;
  posts: Posts[];
  tasks: Tasks[];
};

const homePageModifiers = {
  posts: merged<Posts[]>({ matchOn: 'id' }),
  tasks: deepMerged<Tasks[]>().deferred('sidebar'),
} satisfies ModifierTree<HomePageData>;

const homePage = definePage<HomePageData, typeof homePageModifiers>({
  component: 'Home',
  modifiers: homePageModifiers,
  requireShared: ['user'],
});

export type HomePageProps = PageProps<typeof homePage>;
```

When handling Inertia requests, render your page by invoking the page definition with the data you want to send.

```ts
inertia.render(
  homePage({
    title: 'Welcome',
    description: 'Hello, World!',
    posts: () => getPosts(req.params.page),
    tasks: () => getTasks(),
  })
);
```

On the client, use the generated page props type.

```tsx react icon="react"
import type { HomePageProps } from '~/server/inertia';

export function Home({ title, description, posts, tasks, user }: HomePageProps) {
  return (
    <div>
      <h1>{title}</h1>
      <p>Hello, {user.name}! {description}</p>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
      {tasks ? (
        <ul>
          {tasks.map((task) => (
            <li key={task.id}>{task.title}</li>
          ))}
        </ul>
      ) : (
        'Loading tasks...'
      )}
    </div>
  );
}
```

## Data-first definitions

With the data-first API:

- every key in `Data` is a prop by default
- `modifiers` only describe exceptions such as deferred, optional, once, or merge behavior
- render values can still be literals or lazy closures
- nested object props can declare nested modifiers

For the best `PageProps<typeof page>` inference, capture your modifier tree in a named constant and type it with `satisfies ModifierTree<Data>`.

If a page has no special behavior, skip `modifiers` entirely.

```ts
const page = definePage<{
  title: string;
  message: string;
}>({
  component: 'Home',
});
```

## Nested modifiers

Nested modifiers are declared as a sparse tree that matches your data shape.

```ts
import { deferred, merged, type ModifierTree } from 'inertia-server';

type DashboardPageData = {
  title: string;
  filters: {
    search: string;
    status: string;
  };
  analyticsPanel: {
    analytics: {
      summary: string;
      chart: string[];
    };
  };
  users: {
    data: User[];
  };
};

const dashboardPageModifiers = {
  analyticsPanel: {
    analytics: deferred('analytics'),
  },
  users: {
    data: merged<User[]>({ matchOn: 'id' }).scroll({ pageName: 'page' }),
  },
} satisfies ModifierTree<DashboardPageData>;

const dashboardPage = definePage<
  DashboardPageData,
  typeof dashboardPageModifiers
>({
  component: 'Dashboard',
  modifiers: dashboardPageModifiers,
});
```

Render values stay data-first as well.

```ts
inertia.render(
  dashboardPage({
    title: 'Overview',
    filters: {
      search: 'Ada',
      status: 'active',
    },
    analyticsPanel: {
      analytics: async () => ({
        summary: 'Engagement up 24%',
        chart: ['Mon 12', 'Tue 18', 'Wed 24'],
      }),
    },
    users: {
      data: () => fetchUsers(),
    },
    $hasMore: {
      'users.data': true,
    },
  })
);
```

Internally, partial reloads and merge metadata use dot paths such as `analyticsPanel.analytics` and `users.data`.

<Note>
This iteration supports either child modifiers on a node or a modifier on the parent path, but not both at the same time.
</Note>

## Lazy loading

When rendering a page, every value can be a literal or a lazy function.

```ts
const page = definePage<{
  foo: string;
  bar: string;
}>({
  component: 'Home',
});

// Option 1
inertia.render(
  page({
    foo: 'foo',
    bar: () => getBar(),
  })
);

// Option 2
inertia.render(
  page({
    foo: () => 'foo',
    bar: getBar(),
  })
);
```

In both cases, the value is resolved only when Inertia needs it, not when `render()` is called.

## Deferred props

Use `deferred()` to keep a prop out of the initial response and fetch it afterwards.

```ts
import { deferred, type ModifierTree } from 'inertia-server';

type DeferredPageData = {
  foo: string;
  permissions: string[];
  teams: string[];
  roles: string[];
};

const deferredPageModifiers = {
  permissions: deferred(),
  teams: deferred('attributes'),
  roles: deferred('attributes'),
} satisfies ModifierTree<DeferredPageData>;

const page = definePage<DeferredPageData, typeof deferredPageModifiers>({
  component: 'Home',
  modifiers: deferredPageModifiers,
});
```

In the example above, `teams` and `roles` are fetched together, while `permissions` is fetched in parallel as a separate deferred group.

## Merging props

Inertia overwrites props with the same name when reloading a page. Use `merged()` when you want partial reloads to append or prepend incoming data instead.

```ts
import { merged, type ModifierTree } from 'inertia-server';

type PostsPageData = {
  posts: { id: number; value: string }[];
};

const postsPageModifiers = {
  posts: merged<{ id: number; value: string }[]>({ matchOn: 'id' }).prepend(),
} satisfies ModifierTree<PostsPageData>;

const page = definePage<PostsPageData, typeof postsPageModifiers>({
  component: 'Home',
  modifiers: postsPageModifiers,
});
```

With `matchOn`, items with the same key are replaced and the rest are appended or prepended.

## Deep merging

Use `deepMerged()` to merge the entire nested structure.

```ts
import { deepMerged, type ModifierTree } from 'inertia-server';

type ChatPageData = {
  chat: {
    messages: { id: number; text: string }[];
    online: number;
  };
};

const chatPageModifiers = {
  chat: deepMerged({ matchOn: 'messages.id' }),
} satisfies ModifierTree<ChatPageData>;

const page = definePage<ChatPageData, typeof chatPageModifiers>({
  component: 'Chat',
  modifiers: chatPageModifiers,
});
```

<Note>
`deepMerged()` is useful when the whole structure should merge together. In most cases, `merged()` with `matchOn`, `append`, or `prepend` is more explicit.
</Note>

## Infinite scrolling

Use `merged().scroll()` to integrate with Inertia's infinite scroll behavior.

```ts
import { merged, type ModifierTree } from 'inertia-server';

type PostsPageData = {
  posts: Posts[];
};

const postsPageModifiers = {
  posts: merged<Posts[]>().scroll({ pageName: 'page' }),
} satisfies ModifierTree<PostsPageData>;

const page = definePage<PostsPageData, typeof postsPageModifiers>({
  component: 'Home',
  modifiers: postsPageModifiers,
});
```

When rendering a page, provide `$hasMore` for every scroll prop.

```ts
inertia.render(
  page({
    posts: () => getPosts(page),
    $hasMore: {
      posts: true,
    },
  })
);
```

To make backend integration easier, read the page parameter name from the page definition.

```ts
function handler(req: Request) {
  const pageQueryParam = postsPage.scrollOptions.posts.pageName;
  const page = req.query[pageQueryParam];
}
```

Nested scroll props use dot paths in `$hasMore`.

```ts
$hasMore: {
  'users.data': true,
}
```

## Prop modifiers

Use these helpers to control how Inertia includes a prop:

- `optional()`: only include when explicitly requested via `only`
- `always()`: always include, even on partial reloads
- `once()`: include on the first request, then keep cached on the client

```ts
import { always, once, optional, type ModifierTree } from 'inertia-server';

type PropModifierPageData = {
  foo: string;
  bar: string;
  baz: string;
};

const propModifierPageModifiers = {
  foo: optional(),
  bar: always(),
  baz: once(),
} satisfies ModifierTree<PropModifierPageData>;

const page = definePage<PropModifierPageData, typeof propModifierPageModifiers>({
  component: 'Home',
  modifiers: propModifierPageModifiers,
});
```

## Legacy schema API

The older schema API still works and stays useful during migration.

```ts
import {
  createInertia,
  deepMergedProp,
  mergedProp,
  prop,
} from 'inertia-server';

const { definePage } = createInertia(...);

const page = definePage({
  component: 'Home',
  props: {
    title: prop<string>(),
    posts: mergedProp<Posts[]>(),
    tasks: deepMergedProp<Tasks[]>().deferred(),
  },
});
```

Prefer the data-first `definePage<Data>({ modifiers })` API for new code. Keep the schema API when you need a backwards-compatible migration path.

## Accessing other page object properties

Flash data and errors are available inside the props object. To access page URL, version, and other metadata, use hooks from your framework of choice.

```tsx react icon="react"
import { usePage } from '@inertiajs/react';

const { url, version } = usePage();

return (
  <div>
    <h1>{url}</h1>
    <p>{version}</p>
  </div>
);
```
